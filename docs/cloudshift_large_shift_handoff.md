# CloudShift 大規模シフトモード 引き継ぎ資料

更新日: 2026-07-23
作業ブランチ: `claude/large-shift-mode-requirements-7j2p2k`

## 1. 現在の到達点

大規模シフトは CloudShift の新規モード `large` として、作成、設定、月間編集、共有、下書き、基準版、集計、PDF/XLSX出力、現場・個人シフトとの同期まで一通り利用できる状態になっている。

初期の設計書では他モード同期を将来対応としていたが、その後の要望を受けて本ブランチで実装した。このため、同期については `docs/cloudshift_large_shift_design.md` の「初期は対象外」という記述より、本資料と実装を新しい仕様として扱うこと。

## 2. 実装済み

### CloudShiftへの統合

- シフト帳作成時に「大規模シフト」を選択できる。
- 大規模シフトを既存の現場マスタと紐づけられる。
- 既存CloudShiftの所有者・共有閲覧・共有編集・PWA・履歴・下書き・復元の仕組みを利用する。
- 保存データは既存の `CloudShiftMonth.entries_per_day` を利用し、大規模シフト専用の正規化処理を通す。
- 保存済みデータを開いた際に同期漏れを補完するキャッチアップ処理がある。

### 設定画面

- メンバーを「レギュラー」と「代務」の列種別に分けて設定できる。
- 過去データで `sub_` から始まる代務列がレギュラーへ戻らない互換処理を追加した。
- シフト選択肢を「ダイヤ」と「休日」のタブに分離した。
- 休日の初期値を次の7種類にした。
  - 法定休
  - 所定休
  - 振休
  - 有休
  - 希望休
  - 希望有休
  - 希望振休
- 内部キー、勤務種別、計算項目、時間設定に利用者向けの説明を付けた。
- 色変更が設定画面のプレビューにも即時反映される。
- 計算設定は「何の判定・集計に使う値か」が分かる表示にした。

### シフト作成画面

- 既存の現場シフトに近いセル、勤務表示、選択状態、ドラッグ操作へ寄せた専用UIを実装した。
- 1クリックでセルまたは勤務を選択し、ダブルクリックで編集モーダルを開く。
- キーボード移動、直接入力、Delete、コピー・貼り付けに対応している。
- 1セルへ複数の勤務を保存できる。
- 複数勤務は横並びではなく縦並びで表示し、日付行の高さが勤務数に応じて伸びる。
- ドラッグはセル全体ではなく勤務1件単位で行う。
- ドロップ先に既存勤務がある場合は入れ替えず、単純に追加する。
- セル全体を安定したクリック・色塗り範囲とし、文字量で当たり判定が変わらない。
- 代務列へ入力する場合は、勤務と担当者をセル単位で指定する。
- コメント、変更マーカー、コメントマーカー、日付・ダイヤ欄のメモ表示を維持し、視認性を上げた。
- 「他現場」は既存CloudShiftに合わせ、別ポップアップで現場検索と既存オプションを選択する。
- 他現場勤務の表示は「現場名＋利用者指定文字列」とし、大規模シフト固有の勤務コード選択にはしていない。

### 勤務時間計算

- CloudShiftから独立した勤務時間計算エンジンを追加した。
- ダイヤ別時間、日付のダイヤ種別、休憩、拘束時間、労働時間、残業、法定・所定休日出勤、連続勤務、休息期間などを計算する。
- 1セル内の複数勤務は時間帯の和集合で集計する。
- 時間帯が重なる場合は `TIME_OVERLAP` を出し、重複時間を二重計上しない。
- 外部から同期された勤務は大規模シフト側のローカル労働時間へ二重計上しない。
- ブラウザ側の即時計算とサーバー側計算を用意している。

### PDF・XLSX

- 大規模シフト専用のPDFとXLSXレンダラーを追加した。
- PDFへセルコメントを出力する。
- PDFの表、文字、ウェイトを以前より大きく・太くし、紙面で読みやすくした。
- 日本語PDF用に `NotoSansJP-SemiBold.ttf` を同梱した。
- XLSXは「シフト表」「集計」「個人明細」の3シートを出力する。
- 大規模シフトではCSV、カレンダー画像、PWAのICS出力を意図的に非対応としている。

### 現場・個人シフトとの同期

- 大規模シフトのレギュラーメンバーと代務列の担当者を、社員番号を基準に個人・現場シフトへ反映する。
- 大規模シフトから個人シフトへは「大規模シフトの現場名＋ダイヤ」として反映する。
- 大規模シフトから現場シフトへは、担当者とダイヤを反映する。
- 個人・現場シフトから大規模シフトへも反映する。
- 大規模シフトと異なる現場の予定も、該当するレギュラーメンバーへ取り込む。
- 現場側でレギュラーに一致しない担当者は、空いている代務列へ担当者名付きで取り込む。
- 同期項目はサーバーを正として保護し、大規模シフト画面から同期予定を消しても保存時に勝手に削除されない。
- 同期元から予定を削除した場合は、大規模シフト側からも削除される。
- 同期されたオプションは内部コードを維持しつつ、画面では表示名を使う。
  - 例: 内部値 `O` は画面上で「大型」と表示する。
  - 追加文字列がある場合は「大型・代務」のように表示する。

## 3. このセッションで修正した主な不具合

- 代務列を保存後に編集画面を開くとレギュラー列として扱われる問題。
- 大規模シフトから個人・現場シフトへの同期が保存時に走らない問題。
- 個人・現場シフトから大規模シフトへの逆同期が走らない、または対象現場に限定され過ぎる問題。
- 逆同期時に代務担当者を配置できない問題。
- 保存時点で同期されなかった過去月を、編集画面を開いた際に補完できない問題。
- 他モードから同期したオプションが「大型」ではなく `O` のような内部コードで表示される問題。
- PDFにセルコメントが出ない問題。
- PDFの表と文字が細く小さい問題。
- 複数勤務をドラッグするとセル内の勤務がまとめて移動する問題。

## 4. 未完成・次のセッションで最優先の項目

### 大規模シフトを含む重複チェック

現状、CloudShiftの「重複チェック」APIは `large` を明示的に拒否している。重複チェック画面のモード選択も `scene` と `person` のみである。

現在検出できるのは、大規模シフトの同一セルに入れたローカル勤務同士の時間重複だけである。これは勤務時間計算上の情報警告であり、CloudShift全体の重複チェックとは別物。

次回は以下を満たす形で実装する。

1. 人物と日付を基準に、大規模・現場・個人シフトを横断して比較する。
2. 人物の同定は社員番号を優先し、社員番号がない場合のみ正規化した氏名を慎重に利用する。
3. 大規模シフトのローカル勤務は比較対象にする。
4. 現場・個人シフトから大規模シフトへ同期された鏡像データは、元予定との重複として数えない。
5. 鏡像の判定には `source_project_id`、`sync_source_entry_id`、同期元月・日などの来歴を使う。
6. 同じ人物・日付でも、既存のオプション別重複ルールと大規模シフトの実時間帯を尊重する。
7. 休日と勤務の同日混在を、単なる勤務重複とは区別して分かりやすく警告する。
8. 大規模シフト画面とCloudShiftの重複チェック画面の両方から結果を確認できるようにする。
9. 同期削除、代務列、他現場、複数勤務、社員番号なし、同姓同名をテストする。

単純に大規模シフトのエントリを既存比較関数へ渡すだけでは、同期で複製された同じ予定を重複として誤検出する。また、既存比較関数は比較対象を同一モードに限定しているため、API・UI・比較用正規化モデルをまとめて見直す必要がある。

主な着手箇所:

- `app/tools/cloudshift.py`
  - `/api/conflict-check` の `LARGE_MODE` 拒否
  - 大規模シフトと他モードを比較用レコードへ正規化する処理
- `app/tools/shiftersync_check.py`
  - 現在は同一モード前提の比較ロジック
  - 同期来歴を使った鏡像除外
- `app/templates/_cloudshift_script.html`
  - 重複チェック画面が `scene` / `person` の2択になっている
- `app/static/cloudshift/js/cloudshift_large.js`
  - 大規模編集画面上の警告表示
- `tests/test_cloudshift.py`
  - 既存重複チェックの回帰テスト
- `tests/test_cloudshift_large_integration.py`
  - 大規模・現場・個人を横断した新規テスト

### 今回の対象外または未検証

- 自動シフト作成・アシスト機能の大規模モード対応。
- 既存テンプレート機能の大規模モード対応。
- 要代務シフト帳の「代務要請」ワークフローとの直接連携。大規模シフトの代務列とは別機能。
- 有休マネージャーとの申請・残数まで含めた完全な連携。休日名称と同期可能なデータ構造は合わせたが、申請系の一連動作は未実装・未検証。
- CSV、カレンダー画像、ICS出力。
- 60名に近い最大規模での実ブラウザ性能・印刷性能の負荷試験。

既存CloudShiftの機能をどこまで大規模モードへ追加するかは、重複チェック後に利用者へ確認してから広げる。

## 5. データ上の注意

- 1人×1日は1エントリだが、その中の `assignments` に複数勤務を保持する。
- ローカル勤務は `source_type="local"`。
- 他現場ボタンで追加した勤務や同期勤務は、現場名、オプション、表示用文字列、同期元IDを個別に保持する。
- 同期勤務は勤務時間集計から除外している。これは同じ勤務の二重集計を防ぐためであり、重複がないことを意味しない。
- 代務列の列定義は `column_type="substitute"`。担当者は日ごとのエントリに `employee_number` / `employee_name` を持つ。
- 設定から使用中メンバーや使用中コードを削除しようとすると競合エラーになる。
- コメントだけの変更は「変更あり」マーカーの判定対象外。

## 6. 検証

PR作成前の最終確認として、次を実行した。

```powershell
pytest -q tests/test_worktime_engine.py tests/test_worktime_api.py tests/test_cloudshift_large_core.py tests/test_cloudshift_large_integration.py tests/test_cloudshift.py
```

結果: **125 passed（288.33秒）**

重点的に確認する内容:

- サーバー計算とJavaScript計算の一致。
- 複数勤務の時間帯結合と重複警告。
- 大規模シフトの作成、設定、保存、下書き、共有編集、基準版、履歴、復元。
- PDF/XLSXを実際に読み戻せることと、PDFからコメント文字列を抽出できること。
- レギュラー・代務を含む大規模→個人・現場の同期。
- 個人・同一現場・他現場→大規模の同期。
- 内部オプション `O` が表示用「大型」として保存されること。
- 同期元削除が大規模シフトへ反映されること。
