# CloudShift 大規模シフトモード 引き継ぎ資料

更新日: 2026-07-31
作業ブランチ: `claude/large-shift-mode-holidays-iazf4e`（休日ルール・36協定/960集計・休憩上書き）
前回ブランチ: `claude/large-shift-mode-analysis-js37zr`（同期タイミング再設計・同期勤務の時刻設定）

## 1. 現在の到達点

大規模シフトは CloudShift の新規モード `large` として、作成、設定、月間編集、共有、下書き、基準版、集計、PDF/XLSX出力、現場・個人シフトとの同期まで一通り利用できる状態になっている。

初期の設計書では他モード同期を将来対応としていたが、その後の要望を受けて本ブランチで実装した。このため、同期については `docs/cloudshift_large_shift_design.md` の「初期は対象外」という記述より、本資料と実装を新しい仕様として扱うこと。

## 2. 実装済み

### CloudShiftへの統合

- シフト帳作成時に「大規模シフト」を選択できる。
- 大規模シフトを既存の現場マスタと紐づけられる。
- 既存CloudShiftの所有者・共有閲覧・共有編集・PWA・履歴・下書き・復元の仕組みを利用する。
- 保存データは既存の `CloudShiftMonth.entries_per_day` を利用し、大規模シフト専用の正規化処理を通す。
- 保存済みデータを開いた際に同期漏れを補完するキャッチアップ処理がある。

### 設定画面

- メンバーを「レギュラー」と「代務」の列種別に分けて設定できる。
- 過去データで `sub_` から始まる代務列がレギュラーへ戻らない互換処理を追加した。
- シフト選択肢を「ダイヤ」と「休日」のタブに分離した。
- 休日の初期値を次の7種類にした。
  - 法定休
  - 所定休
  - 振休
  - 有休
  - 希望休
  - 希望有休
  - 希望振休
- 内部キー、勤務種別、計算項目、時間設定に利用者向けの説明を付けた。
- 色変更が設定画面のプレビューにも即時反映される。
- 計算設定は「何の判定・集計に使う値か」が分かる表示にした。

### シフト作成画面

- 既存の現場シフトに近いセル、勤務表示、選択状態、ドラッグ操作へ寄せた専用UIを実装した。
- 1クリックでセルまたは勤務を選択し、ダブルクリックで編集モーダルを開く。
- キーボード移動、直接入力、Delete、コピー・貼り付けに対応している。
- 1セルへ複数の勤務を保存できる。
- 複数勤務は横並びではなく縦並びで表示し、日付行の高さが勤務数に応じて伸びる。
- ドラッグはセル全体ではなく勤務1件単位で行う。
- ドロップ先に既存勤務がある場合は入れ替えず、単純に追加する。
- セル全体を安定したクリック・色塗り範囲とし、文字量で当たり判定が変わらない。
- 代務列へ入力する場合は、勤務と担当者をセル単位で指定する。
- コメント、変更マーカー、コメントマーカー、日付・ダイヤ欄のメモ表示を維持し、視認性を上げた。
- 「他現場」は既存CloudShiftに合わせ、別ポップアップで現場検索と既存オプションを選択する。
- 他現場勤務の表示は「現場名＋利用者指定文字列」とし、大規模シフト固有の勤務コード選択にはしていない。

### 勤務時間計算

- CloudShiftから独立した勤務時間計算エンジンを追加した。
- ダイヤ別時間、日付のダイヤ種別、休憩、拘束時間、労働時間、残業、法定・所定休日出勤、連続勤務、休息期間などを計算する。
- 1セル内の複数勤務は時間帯の和集合で集計する。
- 時間帯が重なる場合は `TIME_OVERLAP` を出し、重複時間を二重計上しない。
- 外部から同期された勤務は大規模シフト側のローカル労働時間へ二重計上しない。
- ブラウザ側の即時計算とサーバー側計算を用意している。

### PDF・XLSX

- 大規模シフト専用のPDFとXLSXレンダラーを追加した。
- PDFへセルコメントを出力する。
- PDFの表、文字、ウェイトを以前より大きく・太くし、紙面で読みやすくした。
- 日本語PDF用に `NotoSansJP-SemiBold.ttf` を同梱した。
- XLSXは「シフト表」「集計」「個人明細」の3シートを出力する。
- 大規模シフトではCSV、カレンダー画像、PWAのICS出力を意図的に非対応としている。

### 現場・個人シフトとの同期（2026-07-30 に同期タイミングを再設計）

- 大規模シフトのレギュラーメンバーと代務列の担当者を、社員番号を基準に個人・現場シフトへ反映する。
- **大規模 → 個人・現場: 大規模シフトの保存・公開・設定変更・復元・月追加のタイミングで押し出す**（従来どおり）。
- **個人・現場 → 大規模: 大規模シフトを「開いたタイミング」で表示月に取り込む**。
  - 他帳の保存時には大規模帳へ書き込まない（`_resync_shift_month` は大規模ターゲットをスキップ）。
    編集中の大規模帳が予測できないタイミングでリビジョン更新され 409 になる問題を解消するため。
  - 開いたときの同期（`_catch_up_large_shift_sync`）は、オーナー画面・共有ユーザー・
    共有URL（閲覧/編集/ViewPWA）のどの経路で開いても実行される。押し出しと取り込みの両方向を行う。
  - 対象月は「実際に画面へ表示される月」（指定月 → 実カレンダー当月 → 最新月）。
    以前は最新月固定だったため、当月を表示しても同期されないバグがあった。
  - ソース側でエントリが消えていた場合の残留同期の剥がし、同期元帳の削除や月コピーで生じた
    孤児同期割当の掃除（`_prune_orphan_large_sync_assignments`）も開いたときに行う。
- 大規模シフトへの取り込みでは、同じセルへ同期し直す際に時刻上書き等のセル単位設定を引き継ぐ。
- 大規模シフトと異なる現場の予定も、該当するレギュラーメンバーへ取り込む。
- 現場側でレギュラーに一致しない担当者は、空いている代務列へ担当者名付きで取り込む。
- 同期項目はサーバーを正として保護し、大規模シフト画面から同期予定を消しても保存時に勝手に削除されない。
- 同期元から予定を削除した場合は、次に大規模シフトを開いたときに大規模側からも削除される。
- 同期されたオプションは内部コードを維持しつつ、画面では表示名を使う。
  - 例: 内部値 `O` は画面上で「大型」と表示する。
  - 追加文字列がある場合は「大型・代務」のように表示する。
- 保存確定後の同期は `_best_effort_shift_sync` 経由のベストエフォート実行にし、
  同期の失敗で保存済みレスポンスを 500 にしない（ログに残して次回開いたときに自己修復）。
- 過去データに設定から消えたメンバーIDの行が残っていても、読み取り・同期・保存が止まらない
  よう、サーバー保存済みデータの正規化は寛容モード（`_normalize_project_entries_for_sync`）で行う。
  クライアント入力の検証は従来どおり厳格（未登録メンバーは 400）。

### 休日ルールと36協定・特別条項・960時間の集計（2026-07-31 追加）

- **これ以前は「休日出勤」を判定する仕組みが実質的に無かった**。セルの `holiday_kind` は
  データ構造としては存在したが、セル編集画面が保存のたびに空文字へ戻していたため、
  画面からは設定できなかった。暦から求める `day_type`（平日/土曜/日祝）はダイヤの時間
  セットを選ぶためだけのもので、休日出勤の判定には使っていない。
- メンバーごとに **法定休日 / 所定休日** を設定できるようにした。指定方法は 2 種類。
  - **曜日**（0=日 … 6=土。複数選択可）
  - **指定日**（`YYYY-MM-DD` の配列。曜日より優先）
  - 共通ルール `settings.holiday_rule` と、メンバー個別 `member.holiday_rule`
    （`mode: "default" | "custom"`）の 2 段構え。既定は日曜=法定休日 / 土曜=所定休日。
  - 同じ日が法定・所定の両方に当たる場合は法定休日が勝つ。
- セル側の `holiday_kind` は「休日区分のその日だけの上書き」に意味を変えた。
  `""`=ルールに従う / `"none"`=その日だけ所定労働日 / `"scheduled"` / `"legal"`。
  振替出勤は `"none"` で表現する。
- 集計軸を 3 本に分けた。① `payroll_overtime_minutes`（所定労働日の残業）
  ② `scheduled_holiday_work_minutes` ③ `legal_holiday_work_minutes`。
  そのうえで次を返す（`worktime_engine` 1.2.0 / `cloudshift_large_calc.js` 1.2.0-js）。
  - `agreement36_minutes` = ①+②+③（36協定対象）
  - `special_clause_minutes` = ①+②（特別条項対象）
  - `annual960_minutes` = ①+②（960対象・当月分）
- **960対象の年度累計**（4月〜翌年3月）はサーバー計算。`/worktime` のレスポンスに
  `fiscal_year_totals` を追加し、同じ帳の年度内で保存済みの月を合計する
  （`cloudshift_large.calculate_large_fiscal_year`）。月単位の計算失敗はその月を除いて継続し、
  実際に合計した月キーを `months` で返す。ブラウザ側は当月しか持てないため、
  画面を開いた直後に先読みし、年度累計だけを取り込む（当月集計はローカル計算を維持）。
- **有休・希望有休の所定時間換算**。`leave_kind == "paid"` の日を所定労働時間として数え、
  `paid_leave_credit_minutes` / `paid_leave_days` / `work_with_paid_total_minutes` を返す。
  実労働時間（`work_total_minutes`）には足さず、表下部で「労働計 X:XX ＋Y:YY」と分けて出す。
  1日あたりは `settings.paid_leave_work_minutes`、未設定ならその日の所定拘束 − 共通休憩。
- PDF/XLSX の休日マーク（所/法）も休日ルール由来に変更し、集計シートへ ①②③・36協定・
  特別条項・960（当月/年度累計）・有休換算の列を追加した。

### セル単位の休憩時間上書き（2026-07-31 追加）

- 従来はセルで上書きできるのが始業・終業（＝拘束時間）と所定拘束だけだった。
  `break_override_minutes` を追加し、その日の休憩時間も上書きできるようにした。
- 優先順位は **セルの上書き → ダイヤ個別の休憩 → 共通設定の休憩**。
  `0` も有効値として扱う（その日は休憩なし）。
- 同期勤務のみのセル（時刻上書きで集計する日）にも適用される。
- 基準版比較・PDF/XLSX の変更判定にも `break_override_minutes` を含めた。

### 同期勤務の勤務時間設定（2026-07-30 追加）

- 他帳から同期された勤務だけのセルは従来 `external`（時間未連携）として集計 0 だった。
- セル編集の「始業・終業の上書き」を設定すると、その時間で拘束・労働・残業・休出に集計される
  （`worktime_engine` 1.1.0 / `cloudshift_large_calc.js` 1.1.0-js の両方に実装、パリティテストあり）。
- 休日出勤マーク（法定/所定）との組み合わせは休日勤務として集計する。
- 時刻上書き未設定の同期セルは従来どおり `external` のまま集計しない。

## 2-1. 移行時の注意（2026-07-31）

- 既存の帳は `settings.holiday_rule` を持たないため、読み込み時に既定値
  （日曜=法定休日 / 土曜=所定休日）が入る。**これまで 0 だった休日出勤の集計が、
  土日に勤務がある帳では数字を持ち始める**。土日休みでない現場は設定の
  「休日ルール」タブを実際の休みに合わせること。
- 曜日番号は JavaScript の `Date#getDay` に合わせて **0=日曜**。Python 側は
  `(date.weekday() + 1) % 7` で変換している。両実装で同じ番号体系を使うこと。
- 休日区分の判定は必ず `cloudshift_large.effective_holiday_kind` /
  `cloudshift_large_calc.js` の `effectiveHolidayKind` を通す。
  `entry["holiday_kind"]` を直接読むと、ルール由来の休日を取りこぼす。

## 3. このセッションで修正した主な不具合

- 代務列を保存後に編集画面を開くとレギュラー列として扱われる問題。
- 大規模シフトから個人・現場シフトへの同期が保存時に走らない問題。
- 個人・現場シフトから大規模シフトへの逆同期が走らない、または対象現場に限定され過ぎる問題。
- 逆同期時に代務担当者を配置できない問題。
- 保存時点で同期されなかった過去月を、編集画面を開いた際に補完できない問題。
- 他モードから同期したオプションが「大型」ではなく `O` のような内部コードで表示される問題。
- PDFにセルコメントが出ない問題。
- PDFの表と文字が細く小さい問題。
- 複数勤務をドラッグするとセル内の勤務がまとめて移動する問題。

## 4. 未完成・次のセッションで最優先の項目

### 大規模シフトを含む重複チェック

現状、CloudShiftの「重複チェック」APIは `large` を明示的に拒否している。重複チェック画面のモード選択も `scene` と `person` のみである。

現在検出できるのは、大規模シフトの同一セルに入れたローカル勤務同士の時間重複だけである。これは勤務時間計算上の情報警告であり、CloudShift全体の重複チェックとは別物。

次回は以下を満たす形で実装する。

1. 人物と日付を基準に、大規模・現場・個人シフトを横断して比較する。
2. 人物の同定は社員番号を優先し、社員番号がない場合のみ正規化した氏名を慎重に利用する。
3. 大規模シフトのローカル勤務は比較対象にする。
4. 現場・個人シフトから大規模シフトへ同期された鏡像データは、元予定との重複として数えない。
5. 鏡像の判定には `source_project_id`、`sync_source_entry_id`、同期元月・日などの来歴を使う。
6. 同じ人物・日付でも、既存のオプション別重複ルールと大規模シフトの実時間帯を尊重する。
7. 休日と勤務の同日混在を、単なる勤務重複とは区別して分かりやすく警告する。
8. 大規模シフト画面とCloudShiftの重複チェック画面の両方から結果を確認できるようにする。
9. 同期削除、代務列、他現場、複数勤務、社員番号なし、同姓同名をテストする。

単純に大規模シフトのエントリを既存比較関数へ渡すだけでは、同期で複製された同じ予定を重複として誤検出する。また、既存比較関数は比較対象を同一モードに限定しているため、API・UI・比較用正規化モデルをまとめて見直す必要がある。

主な着手箇所:

- `app/tools/cloudshift.py`
  - `/api/conflict-check` の `LARGE_MODE` 拒否
  - 大規模シフトと他モードを比較用レコードへ正規化する処理
- `app/tools/shiftersync_check.py`
  - 現在は同一モード前提の比較ロジック
  - 同期来歴を使った鏡像除外
- `app/templates/_cloudshift_script.html`
  - 重複チェック画面が `scene` / `person` の2択になっている
- `app/static/cloudshift/js/cloudshift_large.js`
  - 大規模編集画面上の警告表示
- `tests/test_cloudshift.py`
  - 既存重複チェックの回帰テスト
- `tests/test_cloudshift_large_integration.py`
  - 大規模・現場・個人を横断した新規テスト

### 今回の対象外または未検証

- 自動シフト作成・アシスト機能の大規模モード対応。
- 既存テンプレート機能の大規模モード対応。
- 要代務シフト帳の「代務要請」ワークフローとの直接連携。大規模シフトの代務列とは別機能。
- 有休マネージャーとの申請・残数まで含めた完全な連携。休日名称と同期可能なデータ構造は合わせたが、申請系の一連動作は未実装・未検証。
- CSV、カレンダー画像、ICS出力。
- 60名に近い最大規模での実ブラウザ性能・印刷性能の負荷試験。

既存CloudShiftの機能をどこまで大規模モードへ追加するかは、重複チェック後に利用者へ確認してから広げる。

## 5. データ上の注意

- 1人×1日は1エントリだが、その中の `assignments` に複数勤務を保持する。
- ローカル勤務は `source_type="local"`。
- 他現場ボタンで追加した勤務や同期勤務は、現場名、オプション、表示用文字列、同期元IDを個別に保持する。
- 同期勤務はそのままでは勤務時間集計から除外している（同じ勤務の二重集計防止）。ただし
  エントリの `time_override` を設定した場合は、その時間で勤務として集計する（上記参照）。
- 月コピー（init_mode=copy）では同期割当（`source_type="sync"`）を複製しない。複製すると
  コピー先の月キーと合わない剥がせない同期が残るため。ローカルと「他現場」（`scene`）は残す。
- 代務列の列定義は `column_type="substitute"`。担当者は日ごとのエントリに `employee_number` / `employee_name` を持つ。
- 設定から使用中メンバーや使用中コードを削除しようとすると競合エラーになる。
- コメントだけの変更は「変更あり」マーカーの判定対象外。

## 6. 検証

PR作成前の最終確認として、次を実行した。

```powershell
pytest -q tests/test_worktime_engine.py tests/test_worktime_api.py tests/test_cloudshift_large_core.py tests/test_cloudshift_large_hardening.py tests/test_cloudshift_large_integration.py tests/test_cloudshift_large_conflict.py tests/test_cloudshift_large_sync_timing.py tests/test_cloudshift.py
```

結果: **169 passed（165.98秒）**

重点的に確認する内容:

- サーバー計算とJavaScript計算の一致（休日ルール・休憩上書き・有休換算を含む）。
- 曜日ルールと指定日ルールで、同じ勤務が残業／所定休日労働／法定休日労働に分かれること。
- セルの `holiday_kind="none"` でその日だけ所定労働日に戻せること。
- 休憩上書きが「セル → ダイヤ個別 → 共通設定」の順で効き、`0` も有効なこと。
- 960対象の年度累計が4月〜翌3月で積み上がり、年度をまたぐとリセットされること。
- 複数勤務の時間帯結合と重複警告。
- 大規模シフトの作成、設定、保存、下書き、共有編集、基準版、履歴、復元。
- PDF/XLSXを実際に読み戻せることと、PDFからコメント文字列を抽出できること。
- レギュラー・代務を含む大規模→個人・現場の同期。
- 個人・同一現場・他現場→大規模の同期。
- 内部オプション `O` が表示用「大型」として保存されること。
- 同期元削除が大規模シフトへ反映されること。
